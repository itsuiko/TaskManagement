# frontend — TaskManagement

ボード画面。[要件定義書](../docs/requirements.md) の F-01（ボード表示）・F-02（作成）・F-03（編集）・F-04（削除）・F-05（列間の移動）・F-08（カードの表示内容）を実装している。

## 起動

**バックエンドとデータベースを先に起動しておく**（[ルートの README](../README.md)）。この画面は自分ではデータを保存しない。表示するのは `GET /api/tasks` の結果で、作成・編集・削除・移動はすべて API を呼んだあとに一覧を取り直す。

```
npm install     # 初回のみ
npm run dev     # http://localhost:5173
```

## 検査

```
npm run lint    # oxlint。書き方の検査
npm run build   # tsc による型の検査 → 本番用のビルド
```

**PR を作る前に両方通す**（観点の全体は `.claude/skills/quality-check/SKILL.md`）。フロントに自動テストは無いので、振る舞いは実機で確かめる。

## バックエンドとの繋ぎ方

`vite.config.ts` の `server.proxy` が `/api` を `http://localhost:8080` へ中継する。

ブラウザは 5173、バックエンドは 8080 で**ポートが違うため、そのまま呼ぶと別オリジンとみなされ CORS で弾かれる**。Vite に中継させるとブラウザからは同一オリジンに見えるので、バックエンド側に `@CrossOrigin` を書いて受け入れ先を広げずに済む。これは「API は同一オリジンからのリクエストのみ受け付ける」（[非機能要件](../docs/requirements.md#6-非機能要件)）とも一致する。

`server.strictPort: true` を設定しているため、**5173 が埋まっていると別のポートに逃げずに起動が失敗する**。黙って 5174 で立ち上がると、古いサーバーが 5173 に残ったまま「動いているのに変更が反映されない」状態になるため。
