# frontend — TaskManagement

ボード画面。[要件定義書](../docs/requirements.md) の F-01（ボード表示）と F-08（カードの表示内容）を実装している。

## 起動

**バックエンドとデータベースを先に起動しておく**（[ルートの README](../README.md)）。この画面はデータを持たず、`GET /api/tasks` の結果を表示するだけである。

```
npm install     # 初回のみ
npm run dev     # http://localhost:5173
```

## ファイルの分け方

| パス | 役割 |
|---|---|
| `src/types.ts` | バックエンドから届く `Task` の形と、画面の 3 列の定義 |
| `src/api.ts` | バックエンドとの通信。**ここ以外から `fetch` を呼ばない** |
| `src/App.tsx` | 読み込みの状態（読み込み中 / 取得できた / 失敗した）を持ち、3 列に振り分ける |
| `src/components/Column.tsx` | 1 列。見出しと件数、カードの並び |
| `src/components/TaskCard.tsx` | カード 1 枚。タイトル・優先度・期限 |

## バックエンドとの繋ぎ方

`vite.config.ts` の `server.proxy` が `/api` を `http://localhost:8080` へ中継する。

ブラウザは 5173、バックエンドは 8080 で**ポートが違うため、そのまま呼ぶと別オリジンとみなされ CORS で弾かれる**。Vite に中継させるとブラウザからは同一オリジンに見えるので、バックエンド側に `@CrossOrigin` を書いて受け入れ先を広げずに済む。これは「API は同一オリジンからのリクエストのみ受け付ける」（[非機能要件](../docs/requirements.md#6-非機能要件)）とも一致する。

`server.strictPort: true` を設定しているため、**5173 が埋まっていると別のポートに逃げずに起動が失敗する**。黙って 5174 で立ち上がると、古いサーバーが 5173 に残ったまま「動いているのに変更が反映されない」状態になるため。
